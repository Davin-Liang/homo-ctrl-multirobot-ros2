# 轨迹记录器等待控制器就绪设计

## 目标

当配置了 `controller_node_name` 时，轨迹记录器在控制器参数服务就绪前不创建里程计订阅、不开始记录，支持“先启动记录器、后启动算法”。

## 行为

- `controller_node_name` 非空：每秒等待 `<follower_ns>/<controller_node_name>/get_parameters`，直到服务可用或进程被 Ctrl-C 终止。
- 服务就绪后只读取一次控制器参数，之后沿用现有的自动标签、图表标题、订阅与首条里程计开始计时逻辑。
- `controller_node_name` 为空：跳过控制器参数查询，直接创建订阅并记录；不会构造非法的双斜杠服务名。

## 范围与验证

- 不设置超时，不改 CSV、绘图、元数据结构或已有延迟节点查询。
- 单元测试覆盖空节点名跳过、服务不可用时重试、服务就绪后继续读取参数。
- README 说明启动顺序与无限等待行为。
