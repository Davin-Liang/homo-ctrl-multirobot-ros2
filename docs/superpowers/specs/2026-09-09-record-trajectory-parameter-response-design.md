# 轨迹记录器等待参数响应设计

## 目标

控制器参数服务可发现但尚未响应时，轨迹记录器继续等待；只有成功收到一次 `GetParameters` 响应后才开始订阅和记录。

## 行为

- 保留既有的每秒服务可用性检查。
- 服务可用后，请求 `CTRL_PARAM_NAMES`；若 2 秒内未收到有效响应，记录等待日志并重新执行服务检查与参数请求。
- 成功收到响应后，保存可读取的数值参数并继续现有初始化流程。
- `controller_node_name` 为空时仍跳过参数查询、直接记录；Ctrl-C/ROS 关闭时停止等待并走正常清理。

## 范围与验证

- 不增加超时总上限，不修改 CSV、绘图、元数据结构、延迟节点查询或输出格式。
- 测试覆盖首次请求超时后重试、成功响应后返回参数，以及 ROS 关闭时停止重试。
