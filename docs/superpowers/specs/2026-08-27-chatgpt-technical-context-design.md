# ChatGPT 技术讨论上下文文档设计

## 目标

新增一份面向网页端 ChatGPT 的中文 Markdown 文档。它应使不了解本仓库的人能够在不先通读源码的情况下，围绕多机器人编队控制、输入延迟、定位链路、避障和实验设计进行准确讨论。

## 读者与使用方式

读者是参与技术讨论的研究者或 AI 助手，而非首次安装 ROS 的用户。文档将作为上传或粘贴给 ChatGPT 的项目上下文，因此优先提供术语、前提、接口和证据状态，而非罗列所有安装细节。

## 内容边界

文档覆盖：平台与 ROS 架构、坐标系与话题约定、仿真/实车定位链路、Leader-Follower 问题定义、主要控制器及延迟补偿、HOCBF 安全滤波、领航轨迹、实验流程、诊断与已知限制。

文档不把历史代码、被 CMake 禁用的可执行目标或未跟踪的结果目录描述成默认可构建、已验证的能力；它们只会被标记为可选或实验性工作。

## 信息结构

1. 项目身份和当前研究问题；
2. 平台、坐标系、命名空间以及仿真/实车的边界；
3. 从传感器到 `/cmd_vel` 的数据流；
4. 建图、定位与控制使用的状态来源；
5. 编队问题、队形几何、齐次控制和离散点切换；
6. 控制器对比，包括模型、延迟处理、避障和编译状态；
7. 延迟、预测与真实系统测量；
8. scan 圆柱拟合与 predictor-HOCBF-QP；
9. 可复现实验拓扑与最小启动流程；
10. 可观测诊断指标、局限性及安全讨论边界；
11. 术语表与适合 ChatGPT 回答的提问模板。

## 事实来源与一致性规则

事实以根目录及各包 README、launch 文件、CMakeLists.txt、控制器源码和 `doc/` 下理论文档为准。若 README 与当前构建配置不一致，构建配置优先；具体来说，当前默认 CMake 仅启用基线 4D 与 4D Artstein，6D Artstein 与 HOCBF 等位于 `if(FALSE)` 分支，必须显式恢复后才能构建。

参数只给出其物理或算法角色和典型默认值，不承诺未经实验覆盖的通用最优性。理论保证须区分名义模型、局部预测近似、仿真验证和实车验证。

## 验收标准

- 文档为独立、可上传的 UTF-8 中文 Markdown，不依赖阅读者访问本地路径。
- 能解释控制器输入、输出、坐标系、延迟定义和控制器之间的差异。
- 明确区分当前构建状态、代码存在状态与实验结论。
- 提供至少一个虚拟 Leader 和一个真实 Leader 的讨论/实验入口。
- 不包含 TBD、TODO 或未标注来源的性能承诺。
